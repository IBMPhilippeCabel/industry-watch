# Security policy

## Reporting a vulnerability

Please **do not open a public issue** for a security problem.
Use GitHub's private reporting: the **Security** tab of this repository, then **Report a vulnerability**.

Useful details: the affected page or script, the steps to reproduce, and the impact you expect.

## Scope

This repository builds a static site (HTML pages generated by `scripts/`) and publishes it with GitHub Pages.
It has no server, no login and no database.

In scope: code injection through feed or AI content into the generated pages, a leaked secret,
a workflow weakness (permissions, untrusted input).

Out of scope: the content of third-party sources, and the services used (GitHub, Groq, GoatCounter).

## What is already in place

- Every link taken from a feed is checked (`http`/`https` only) and every text is stripped of tags
  before it is stored, then escaped again when the pages are generated.
- Secrets (`GROQ_API_KEY`, `GOATCOUNTER_API_KEY`) are given only to the workflow step that needs them.
- Workflow permissions are declared per job; third-party actions are pinned to a commit SHA and
  updated through Dependabot.
